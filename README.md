# Чертёжник

Telegram-бот для самопроверки 3D-моделей по контрольным размерам с чертежа. Пользователь вводит размеры, получает чек-лист и загружает STL. FastAPI проверяет замкнутость сетки, измеряет габариты, ищет простые осевые цилиндрические отверстия и фаски 45°, затем сравнивает измерения с заданным допуском.

## Устройство

```text
Telegram → бот (aiogram) → HTTP → FastAPI
                                ├── POST /parse-dimensions
                                └── POST /analyze-model
```

Бот хранит размеры и состояние диалога в памяти без базы данных. Анализ STL выполняется в отдельном локальном процессе, который завершается при тайм-ауте. STL временно находится в `.runtime/bot-uploads/` и `.runtime/uploads/`; обе копии удаляются после анализа или ошибки. Модели и отчёты не сохраняются. Типы размеров и лимиты задаются в `config.yaml`, токен — в локальном `.env`.

## Требования и получение токена

Нужны Python 3.12 или новее и интернет для Telegram. В Telegram открой [@BotFather](https://t.me/BotFather), отправь `/newbot`, задай отображаемое и уникальное имя бота. Полученный токен храни как пароль и не добавляй в Git. Для меню команд можно отправить BotFather `/setcommands` и указать `start`, `new`, `help`, `cancel`.

## Установка

В папке проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Если система сообщает об отсутствии `venv` или `ensurepip`, установи системный пакет для своей версии Python и повтори создание окружения. В `.env` замени `PASTE_YOUR_BOT_TOKEN_HERE` на токен от BotFather. `API_URL` по умолчанию равен `http://127.0.0.1:8000`.

## Запуск

В первом терминале из папки проекта:

```bash
source .venv/bin/activate
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале из той же папки:

```bash
source .venv/bin/activate
python -m bot
```

Оба процесса должны продолжать работать. Остановка — `Ctrl+C` в каждом терминале. API слушает только `localhost`; открывать порт наружу не нужно. Не запускай две копии бота с одним токеном.

## Проверка в Telegram

1. Открой своего бота по ссылке от BotFather и отправь `/start`, затем `/new`.
2. Отправь размеры, например:

   ```text
   габарит_длина=100, габарит_ширина=50, габарит_высота=10
   отверстие_1_диаметр=10
   ```

3. После чек-листа прикрепи замкнутый STL как **документ**. Для правильной модели бот покажет разделы «Совпало» и «Расхождения»; для неверного отверстия Ø8 мм укажет ожидаемое Ø10 мм и фактическое Ø8 мм. После полного совпадения диалог завершается. При расхождении размеры сохраняются для повторной загрузки.
4. Для повреждённого файла бот вернёт `INVALID_FILE`, для файла больше 10 МБ — `FILE_TOO_LARGE`. После ошибки можно отправить другой STL без повторного `/new`.
5. `/cancel` отменяет диалог. Если бот не отвечает, проверь оба терминала, интернет, токен и `API_URL`.

## Формат и ограничения измерений

Пары `название=значение` разделяются запятыми или переносами строк. Поддерживаются `габарит_длина`, `габарит_ширина`, `габарит_высота`, `габарит_диаметр`, `отверстие_1_диаметр`, `отверстие_1_глубина`, `диаметр_1`, `глубина_1`, `фаска_1`; номера — положительные целые. Единицы: `мм` по умолчанию, `см`, `дюйм`, `in`. Дробная часть пишется через точку. Допуск по умолчанию — ±0,5 мм. В одном сообщении допускается до 2000 символов и 30 уникальных размеров.

STL не хранит единицы измерения: координаты считаются миллиметрами. Габариты пластины сопоставляются с осями X/Y/Z в порядке длина/ширина/высота. Для вала, заданного через `габарит_длина` и `габарит_диаметр`, длиной считается наибольший габарит, а диаметром — совпадающая пара меньших. Поворот детали относительно осей может изменить результат.

Ищутся только круглые отверстия с осью X, Y или Z. Их номера назначаются по положению центров: сначала отверстия вдоль Z, затем X и Y; внутри оси — по координатам центра. Глубина оценивается по протяжённости цилиндрической стенки. Фаски распознаются как переходы около 45° между плоским торцом и боковой поверхностью, параллельные одной из осей. Сложные и наклонные элементы могут быть помечены `не найдено`; это не означает, что их физически нет в модели. Поиск отверстий и фасок в треугольной сетке является приближённым.

## API и тесты

- `POST /parse-dimensions` принимает JSON `{"user_id": 42, "raw_text": "габарит_длина=100"}` и возвращает нормализованные размеры с чек-листом.
- `POST /analyze-model` принимает `multipart/form-data`: `user_id`, `dimensions` (JSON-строка со списком размеров), `file` (STL). Успешный ответ HTTP 200 содержит `status: ok` и `report` с `matches`, `mismatches`, `summary`, `telegram_text`; у каждого совпадения и расхождения есть поле `name`. Если размер не найден, `actual` и `delta` равны `null`.
- Ошибки содержат `status: error`, `code`, `message`: `INVALID_FORMAT` (400), `INVALID_FILE` (422), `FILE_TOO_LARGE` (413). `TIMEOUT` (504) возвращается, когда анализ длится дольше `timeout_sec`; `INTERNAL_ERROR` (500) — при непредвиденном сбое.

Запуск тестов:

```bash
python -m unittest discover -s tests -v
```

Тесты дополнительно используют локальный архив `data/tests.tar.gz`, если он есть; без него соответствующая проверка пропускается. Папки `data/`, `.runtime/`, `notes/`, а также `.env` и `.venv` исключены из Git.
