# Чертёжник

Telegram-бот для самопроверки 3D-моделей по контрольным размерам с чертежа. Текущая версия принимает размеры, проверяет их и выдаёт чек-лист. **Загрузка и анализ STL, а также отчёт о расхождениях пока не реализованы.**

## Как устроен текущий этап

```text
Telegram → бот (aiogram) → HTTP → FastAPI /parse-dimensions
                            ← размеры и чек-лист
```

Бот хранит состояние диалога в памяти; база данных не нужна. После перезапуска бота текущие диалоги сбрасываются. Типы размеров и ограничения заданы в `config.yaml`, токен — в локальном `.env`.

## Требования

- Python 3.12 или новее и доступ к интернету для Telegram-бота.
- Токен бота от [@BotFather](https://t.me/BotFather).

Чтобы создать бота, отправь `@BotFather` команду `/newbot`, укажи отображаемое имя и уникальное имя пользователя, оканчивающееся на `bot`. Полученный токен храни как пароль. Для меню команд можно отправить `/setcommands` и задать `start`, `new`, `help`, `cancel`.

## Установка

В папке скачанного проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Если Python сообщает об отсутствии `venv` или `ensurepip`, установи соответствующий системный пакет для своей версии Python и повтори создание окружения. В `.env` замени `PASTE_YOUR_BOT_TOKEN_HERE` на токен от BotFather. Адрес API по умолчанию — `http://127.0.0.1:8000`; менять `API_URL` обычно не требуется.

## Запуск

Нужны **два терминала** в папке проекта. В первом запусти API:

```bash
source .venv/bin/activate
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Во втором запусти бота:

```bash
source .venv/bin/activate
python -m bot
```

Оба процесса должны продолжать работать, пока ты проверяешь бота. Остановка — `Ctrl+C` в каждом терминале. API слушает только `localhost`, поэтому открывать порт наружу не нужно. Не запускай две копии бота с одним токеном одновременно.

## Проверка в Telegram

1. Открой своего бота по ссылке от BotFather и отправь `/start`, затем `/new`.
2. Отправь сообщение:

   ```text
   габарит_длина=100, габарит_ширина=50
   отверстие_1_диаметр=10
   ```

3. Бот покажет чек-лист с габаритами `100 × 50 мм` и отверстием `Ø10 мм`.
4. Отправь `/new`, затем `габарит_длина=0`. Бот вернёт `INVALID_FORMAT` и попросит исправить сообщение. После этого можно ввести правильные размеры без нового `/new`.
5. `/help` показывает справку, `/cancel` отменяет диалог. Если отправить файл, бот сообщит, что обработка STL будет добавлена позже; файл не скачивается.

Если бот не отвечает на размеры, проверь, что **оба** процесса запущены, адрес `API_URL` верен и в терминалах нет ошибок.

## Формат размеров

Несколько пар `название=значение` разделяются запятыми или переносами строк. Поддерживаются `габарит_длина`, `габарит_ширина`, `габарит_высота`, `отверстие_1_диаметр`, `отверстие_1_глубина`, `диаметр_1`, `глубина_1`, `фаска_1`; номер может быть любым положительным целым числом. Допустимые единицы: `мм` по умолчанию, `см`, `дюйм`, `in`. Дробную часть записывай через точку, например `10.5`.

Сервер переводит значения в миллиметры. В одном сообщении допускается до 2000 символов и 30 уникальных размеров. При ошибке всё сообщение отклоняется. Список разрешённых имён, допуск и лимиты можно менять в `config.yaml`.

## API и тесты

`POST /parse-dimensions` принимает JSON вида `{"user_id": 42, "raw_text": "габарит_длина=100"}` и возвращает `status`, `dimensions`, `checklist`. Неверный ввод получает HTTP 400 с полями `status: error`, `code: INVALID_FORMAT`, `message`. Контракт загрузки STL будет добавлен на следующем этапе.

Локальные тесты не требуют токена или подключения к Telegram:

```bash
python -m unittest discover -s tests -v
```

Структура: `bot/` — Telegram-бот и HTTP-клиент; `backend/` — FastAPI, разбор размеров, модели данных и ошибки; `config.yaml` — настройки; `tests/` — проверки. `.env` и `.venv` исключены из Git.
